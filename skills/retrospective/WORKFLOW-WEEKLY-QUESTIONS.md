# ワークフロー: 週末振り返り質問生成

直近1週間の記録から、思考や感情の背景に気づきを与える振り返り質問を5つ生成する。ユーザーはこの質問に回答を書き込むことで、来週の方針・アクション検討につなげる。

## Phase 0: 進捗管理の登録

**TodoWriteで以下を登録すること：**

```json
[
  { "content": "Phase 1: フィードバックログの読み込み", "status": "pending", "activeForm": "過去のフィードバックを読み込み中" },
  { "content": "Phase 2: データ取得", "status": "pending", "activeForm": "データを取得中" },
  { "content": "Phase 3: 質問生成", "status": "pending", "activeForm": "質問を生成中" },
  { "content": "Phase 4: サブエージェントレビュー", "status": "pending", "activeForm": "サブエージェントレビューを実施中" },
  { "content": "Phase 5: ユーザー確認・修正", "status": "pending", "activeForm": "ユーザー確認・修正を反映中" },
  { "content": "Phase 6: 出力ファイル保存", "status": "pending", "activeForm": "出力ファイルを保存中" },
  { "content": "Phase 7: 完了報告", "status": "pending", "activeForm": "完了報告中" }

```

## Phase 1: フィードバックログの読み込み

`output/feedback-log.md` が存在すれば読み込み、「## 週末振り返り質問」セクションの過去指摘（例: 「〇〇に関する質問が意味不明だった」等）を確認する（存在しない場合はこのPhaseをスキップ）。

同じ問題のある質問を繰り返さないよう、Phase 3で活用する。

## Phase 2: データ取得

直近1週間分のデータを取得する。

→ **[REFERENCE-LIFEGRAPH.md](REFERENCE-LIFEGRAPH.md)** を参照してカレンダーイベント + スプレッドシート補完データを取得
→ **[REFERENCE-DAILY.md](REFERENCE-DAILY.md)** を参照して日次記録データを取得

## Phase 3: 質問生成

取得データの中から、**仕事・人間関係・金銭・健康メンタル**の主要テーマと、その週固有の出来事を特定し、それらに基づいた質問を5つ作成する。

### 質問作成の条件

- 表面的な出来事の確認にとどまらず、思考や感情の背景に気づきを与える質問にすること
- 質問は簡潔にすること
- 来週の方針やアクション検討につながる問いにすること（「何をしたか」で終わらせず「次にどうするか」につながる形にする）
- 質問の意図と、回答から読み取れることを簡潔に説明すること
- Phase 1で確認した過去の指摘（意味不明だった質問の傾向等）を踏まえ、同じ問題を繰り返さない

### 出力フォーマット

```markdown
# 1週間を振り返るための5つの質問（yyyy-MM-dd週）

## 1. 仕事に関する質問
（質問文）
**意図と読み取れること：** （簡潔に）

回答：

## 2. 人間関係に関する質問
（以下、金銭・健康メンタル・その週固有のテーマ、の順で同様に計5問）
```

## Phase 4: サブエージェントレビュー

**Agentツール（`general-purpose`）を起動し、以下の観点でレビューを依頼する：**

- 各質問が来週の方針・アクション検討につながる問いになっているか（単なる事実確認で終わっていないか）
- 意味不明・回答しづらい質問になっていないか
- Phase 1で確認した過去の指摘が反映されているか

エージェントには、生成した5つの質問と、Phase 1で読み込んだfeedback-logの該当箇所を渡す。レビュー結果を受けて、必要な修正を質問に反映する。

## Phase 5: ユーザー確認・修正

生成した5つの質問をユーザーに提示し、修正したい点がないか確認する。

- 指摘があれば、その内容を質問に反映する
- 反映した指摘は `output/feedback-log.md` の「## 週末振り返り質問」セクションに、日付とともに追記する（次回のPhase 1で読み込まれる）
- 指摘がなければ `output/feedback-log.md` への追記は不要

## Phase 6: 出力ファイル保存

`output/yyyyMMdd-weekly-questions.md` に保存する（`yyyyMMdd` は生成日）。

## Phase 7: 完了報告

出力ファイルのパスを報告する。ユーザーはこのファイルに直接回答を書き込む想定であることを伝える。

## 注意事項

- スクリプトがエラーを返した場合は [SETUP.md](SETUP.md) の認証手順を案内
