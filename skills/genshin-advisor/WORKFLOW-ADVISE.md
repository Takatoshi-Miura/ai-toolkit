# アドバイス生成ワークフロー

`/genshin build|party|abyss` 実行時の詳細手順。SKILL.md からステップ2以降として参照される。

## 目次
- ステップ2: データ取得（毎回最新化）
- ステップ3: 分析・アドバイス草案作成
- ステップ4: サブエージェントレビュー（最大3回）
- ステップ5: レポート出力
- ステップ6: フィードバック記録

---

## ステップ2: データ取得（毎回最新化）

ゲームの状況は日々変わるため、**キャッシュを使い回さず毎回APIから最新データを取得する**。

```bash
python3 scripts/fetch.py all
```

`all` は `allchars`（全所持キャラ・聖遺物）と `status`（リアルタイムステータス）を1回のスクリプト呼び出しでまとめて取得する。`references/.genshin_config` から UID・Cookie を自動読み込みし、`data/latest.json` の `allchars`・`status` キーにそれぞれ毎回上書き保存される（`fetched_at` に取得日時、`uid` に対象UIDを含む）。

`status` のみ必要な場合（例: `/genshin status` 単体実行）は `python3 scripts/fetch.py status` のように個別コマンドで取得してよい。

**あわせて `references/feedback.md` を読み**、過去に記録されたユーザーの評価傾向・プレイスタイルの好みを把握する（例: 「脳筋編成が好き」「元素熟知型は好まない」等）。ステップ3の分析・ステップ5のレポート作成に活かす。`feedback.md` が空、または該当する記録がない場合は以降のステップで参照しなくてよい。

---

## ステップ3: 分析・アドバイス草案作成

`data/latest.json` の該当キー（`allchars` / `status`）を読み、`references/analysis-guide.md` の観点とステップ2で把握した `feedback.md` の内容を踏まえて分析する。

**最新環境情報の確認**: 主力候補（スコア上位、メインDPS/サブDPS候補）のキャラについて、WebSearchで「[キャラ名] 最新 ビルド おすすめ」「[キャラ名] 環境 ティアリスト」等を検索し、`analysis-guide.md` の固定基準（メイン適正・サブオプ優先度・セット効果評価）と食い違いがないか確認する。全所持キャラ分の検索は不要で、主力候補に絞る。個別記事を深掘りしたい場合のみWebFetchで該当URLを取得する。差異があれば草案に反映する。

この時点の出力は最終回答ではなく「草案」として扱い、ステップ4のレビューに回す。

---

## ステップ4: サブエージェントレビュー（最大3回）

Agent ツールで独立したレビュー用サブエージェント（`general-purpose`）を起動し、ステップ3の草案をレビューさせる。

レビュー観点（プロンプトに含める）:
- `references/analysis-guide.md` の評価基準（メイン適正・サブオプ優先度・スコア閾値等）と矛盾していないか
- `references/feedback.md` に記録された過去の好み・評価傾向と矛盾する提案をしていないか
- `data/latest.json` の実データと矛盾する記述（存在しないキャラへの言及等）がないか
- 出力フォーマット（`references/analysis-guide.md` 記載のテンプレート）に沿っているか
- 草案の推奨内容（ビルド・編成）が最新の環境情報と矛盾していないか。WebSearchで主力キャラの「[キャラ名] 最新 ビルド」「[キャラ名] 環境 ティアリスト」等を検索し確認する

サブエージェントには本会話の文脈が渡らないため、プロンプトに草案本文・`references/analysis-guide.md` の該当部分・`references/feedback.md` の内容に加え、`WebSearch`/`WebFetch` の使用が許可されていること・検索クエリ例を自己完結で含める。

指摘があれば草案を修正し、再度レビューする。**最大3回**まで繰り返し、それでも解消しない指摘は「既知の留意点」として最終回答に注記する。

---

## ステップ5: レポート出力

レビュー確定後の内容を、ユーザーへの回答として表示すると同時に `output/report_YYYYMMDD_HHMM.md`（実行日時ごとに1ファイル、上書きしない）として保存する。

レポートには以下を含める:
- 実行日時・対象UID・コマンド種別
- 分析結果本文（`references/analysis-guide.md` 記載の出力フォーマット）
- サブエージェントレビューで解消しなかった留意点（あれば）

---

## ステップ6: フィードバック記録

回答後、ユーザーから提案内容への評価コメント（「これは違う」「これは役立った」等）やプレイスタイルの好みへの言及があった場合、記録内容を提示し「よろしいですか？」と確認を取ってから `references/feedback.md` に追記する。確認なしに自動追記しない。

追記フォーマット:

```
## YYYY-MM-DD
- [評価] コメント内容
- [好み] プレイスタイルの好み
```
